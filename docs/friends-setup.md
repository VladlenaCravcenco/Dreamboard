# Друзья и личные списки желаний

## Подключение

1. В Supabase проекта `tbtzzpnshhsmpvyjjiyf` открыть SQL Editor → New query.
2. Выполнить весь файл `supabase/migrations/20261102010000_private_wishlists.sql` один раз. Он создаёт четыре новые таблицы и функции; существующие мечты не меняет. Для проекта с миграциями CLI применить обычным `supabase db push`.
3. Опубликовать код вместе с `vercel.json`: GitHub → Vercel. Этот файл нужен для прямого открытия `/invite/<token>` и `/friends/<id>`.
4. Supabase Site URL: `https://dreamboard-three.vercel.app/`. Разрешить этот же URL в Redirect URLs. Google-вход возвращается на корень; приглашение хранится в sessionStorage и открывается после входа в той же вкладке. Для подтверждения почты в другой вкладке открыть исходную ссылку повторно после входа.
5. Проверить на двух аккаунтах: A включает свою ссылку; B открывает её, сохраняет A и отмечает желание; A не видит отметку. Повторить в обратную сторону. Изменение выбранной мечты A появляется у B при обновлении или в течение 15 секунд активной вкладки.

До применения миграции раздел показывает сообщение об отсутствующем обновлении базы. Код сам не создаёт таблицы и не открывает доступ к существующим желаниям.

## Поведение

- Друзья → Моя ссылка: имя для друзей, включение доступа, выбор конкретных желаний либо всех текущих и будущих. Доступ по умолчанию выключен.
- Ссылка — случайный UUID. Нет каталога пользователей или поиска. Любой получатель ссылки после входа может сохранить список; её можно переслать, поэтому это не индивидуальное приглашение по email.
- Друзья сначала отображаются карточками. Сохранение одностороннее: чтобы обменяться списками, каждый отправляет свою ссылку.
- Видны только имя, название/категория/фото/описание/бюджет активных желаний. Не передаются email, накопления, задачи, личные заметки, воспоминания.
- «Хочу подарить» — приватная отметка текущего пользователя. Это не эксклюзивная бронь: разные люди могут выбрать один подарок, не видя чужих решений.
- Завершённые, удалённые или исключённые из доступа желания не показываются. Отключение доступа действует для ссылок и сохранённых друзей. Повторное включение восстанавливает прежний доступ.
- Замена ссылки отзывает старую ссылку, сохранённые связи и связанные отметки. Друзьям нужно отправить новую ссылку.
- Изменения подтягиваются раз в 15 секунд в активной вкладке и при возврате к ней. Это polling, не Supabase Realtime.

## Проверки

`npm test` и `npm run build`.

`tests/wishlist-security.mjs` запускает реальную SQL-миграцию в PGlite (PostgreSQL WASM) с тремя пользователями и ролями Supabase. Проверяет владение выбранными мечтами, отсутствие лишних полей, недоступность таблиц напрямую, личные отметки, сохранённый доступ, отключение, замену ссылки и запрет anonymous RPC.

Пример установки тестового движка вне проекта:

```sh
npm install --prefix /tmp/dreamboard-db-test @electric-sql/pglite
PGLITE_MODULE=/tmp/dreamboard-db-test/node_modules/@electric-sql/pglite/dist/index.js node tests/wishlist-security.mjs
```

Изолированная UI-демонстрация: `node tests/build-preview.mjs`. Приглашение в тестовом сервере: `/invite/40000000-0000-0000-0000-000000000001`. Данные демонстрации находятся только в QA-адаптере; он не входит в production build.
